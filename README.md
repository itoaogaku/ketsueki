# 血液検査データ分析アプリ

選手の血液検査データをNotionに蓄積し、平均値の推移や1寮生・2寮生の違い、試合結果との相関を確認できるダッシュボードです。Next.js製で、Vercelにデプロイして使うことを想定しています。

## 主な機能

- 血液検査項目ごとの月次平均値の推移グラフ
- 1寮生・2寮生を選択して比較（両方選択で2本の線を並べて表示）
- 選手を絞り込んでの表示
- グラフと同じ内容のテーブル表示切り替え
- 試合結果（Notion上の既存データベース）との相関分析
  - 血液検査項目 × 試合指標の組み合わせを自動で総当たり計算し、相関が強い順に一覧表示
  - 散布図と相関係数(r)、簡単な解釈コメントを表示
- Notion未接続の状態でもサンプルデータで動作を確認可能

データソースはNotionのデータベースです。血液検査データ・試合結果データのどちらも、**アプリ側で列（プロパティ）の種類を自動認識**します。数値型のプロパティはすべて「検査項目」または「試合指標」として扱われるため、Notion側の列構成を変えても、アプリの改修なしに反映されます。

## セットアップ

### 1. 依存関係のインストール

```bash
npm install
```

### 2. Notionインテグレーションの作成

1. https://www.notion.so/profile/integrations を開き、「新しいインテグレーション」を作成します。
2. 作成後に表示される「Internal Integration Secret」をコピーします（これが `NOTION_TOKEN` です）。

### 3. 環境変数の設定

`.env.example` を `.env.local` としてコピーし、値を埋めます。

```bash
cp .env.example .env.local
```

```
NOTION_TOKEN=（上で取得したシークレット）
NOTION_BLOOD_DATABASE_ID=（後述の手順4で作成、または既存DBのID）
NOTION_GAMES_DATABASE_ID=（既存の試合結果DBのID）
NOTION_PARENT_PAGE_ID=（新規にDBを作成する場合のみ、作成先ページのID）
```

データベースIDは、NotionでそのページのURLを開いたときの、`https://www.notion.so/xxxx?v=...` の `xxxx` 部分（ハイフンなし32文字）です。

> **重要**: Notion APIは、統合（integration）が「接続」されたページ・データベースにしかアクセスできません。使いたいページ／データベースを開き、右上の「…」メニュー→「コネクト」から、作成したインテグレーションを追加してください（血液検査DBと試合結果DBの両方で必要です）。

### 4. 血液検査データベースの準備

まだ血液検査用のNotionデータベースがない場合は、以下のコマンドで自動作成できます（`NOTION_PARENT_PAGE_ID` に指定した親ページの配下に作成されます）。

```bash
npm run setup:notion
```

作成されるプロパティ:

| プロパティ名 | 型 | 用途 |
|---|---|---|
| 選手名 | タイトル | 選手名 |
| 検査日 | 日付 | 検査を実施した日 |
| 寮 | セレクト（1寮生 / 2寮生） | **その検査を受けた時点**でどちらの寮にいたか。寮の入れ替えがあっても検査ごとに正しく記録できます |

血液検査の項目（Hb、Fe、CKなど）は固定の列にせず、**CSVインポート時にNotion側へ自動追加**する方式にしています（手順5参照）。すでにNotion上に血液検査DBがある場合は、`npm run setup:notion` を実行せず、既存DBのIDを `NOTION_BLOOD_DATABASE_ID` に設定するだけで構いません。

試合結果DBも新規作成したい場合は `npm run setup:notion -- --with-games` を実行してください（すでにある場合は既存DBのIDを `NOTION_GAMES_DATABASE_ID` に設定するだけでOKです）。

### 5. 過去データ（CSV）のインポート

過去の血液検査データをCSVで用意し、Notionに取り込みます。列の例は `data/blood-data.example.csv` を参照してください。

必須列:
- `選手名`
- `検査日`（`YYYY-MM-DD` 形式）

推奨列:
- `寮`（`1寮生` または `2寮生`。**検査を受けた時点の所属寮**を行ごとに記入してください）

それ以外の列は、そのままNotion上の検査項目（数値プロパティ）として扱われます。列名は自由に決めて構いません（例: `Hb(ヘモグロビン)`、`Fe(血清鉄)` など）。Notion側にまだ存在しない列は、インポート時に自動でNumber型プロパティとして追加されます。

```bash
# 内容を確認するだけ（Notionへは書き込まない）
npm run import:csv -- data/blood-data.csv --dry-run

# 実際にインポート
npm run import:csv -- data/blood-data.csv
```

同じCSVを再実行しても、「選手名＋検査日」が一致する行は重複登録されないようにスキップされます。

### 6. ローカルで確認

```bash
npm run dev
```

http://localhost:3000 を開くと、ダッシュボードが表示されます。`NOTION_TOKEN` / `NOTION_BLOOD_DATABASE_ID` が未設定の場合は、自動的にサンプルデータで動作を確認できます（画面上部に「サンプルデータ表示中」と表示されます）。

## 試合結果データベースについて

既存の試合結果データベースをそのまま使えるよう、アプリはプロパティを次のルールで自動認識します。

- 日付型のプロパティ → 試合日として使用
- 数値型のプロパティ → 「試合指標」として相関分析・一覧の対象に（得点、失点、防御率など、複数あってもすべて自動で対象になります）
- セレクト／ステータス／テキスト型のプロパティ → ラベルとして表示（勝敗など）
- プロパティ名に「相手」または「対戦」を含むもの → 対戦相手として表示

既存DBのプロパティ名がこれと異なっていても、型さえ合っていれば動作します。うまく認識されない場合は、プロパティの型（日付・数値など）を確認してください。

## 相関分析の考え方

「血液検査項目 × 試合指標」の各組み合わせについて、各試合の**直前N日間**（既定7日間、UIで3/7/14/30日に切り替え可能）に測定された血液検査値の平均と、その試合の指標値との相関係数（ピアソンの積率相関係数）を計算しています。

- あくまで統計的な傾向であり、因果関係を示すものではありません
- サンプル数（n）が小さいと係数が不安定になりやすいため、n の値もあわせて確認してください
- 「相関が強い組み合わせ」一覧は、意味のありそうな組み合わせを見つけるための探索的な機能です。実際の解釈は医療・栄養の専門家も交えて検討することをおすすめします

## Vercelへのデプロイ

1. このリポジトリをGitHubにpushします。
2. https://vercel.com で「Add New... → Project」からこのリポジトリをインポートします。
3. Vercelの Project Settings → Environment Variables に、`.env.local` と同じ内容（`NOTION_TOKEN` / `NOTION_BLOOD_DATABASE_ID` / `NOTION_GAMES_DATABASE_ID`）を設定します（`NOTION_PARENT_PAGE_ID` はセットアップ用スクリプト専用なので本番には不要です）。
4. Deployを実行します。以降はこのブランチにpushするたびに自動でデプロイされます。

## 技術構成

- Next.js (App Router) + TypeScript + Tailwind CSS
- Notion API (`@notionhq/client`) — データベースをそのままデータストアとして利用
- Recharts — グラフ描画
- データ取得はサーバー側（Notionトークンはブラウザに露出しません）で行い、`app/page.tsx` から `Dashboard` コンポーネントに渡しています
- `app/api/*` はプログラムからのアクセスや今後の拡張用に用意したAPIエンドポイントです
